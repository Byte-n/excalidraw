# Phase Workflow

## 开始前

- 读取 `AGENTS.md`，再按 `docs/README.md` 加载与任务相关的 spec、ADR 与既有计划。
- 分析与制定方案前先校对代码与测试现状；文档内容必须能被代码或测试验证。
- 用 `git worktree list`、`git status --short`、`git rev-parse HEAD` 核对现场；不要依据过期对话状态继续。
- 涉及新旧逻辑、数据或协议兼容时，先让用户明确选择：正常处理兼容，或不处理兼容；选择结果写入计划的局部决策。
  - 正常处理兼容：按用户确认的兼容方案实施。
  - 不处理兼容：完全不处理、不提及、不留痕历史逻辑，直接按最新逻辑破坏性实现；除计划的兼容选择记录外，不得保留兼容分支、迁移、开关或回退路径，不得在代码、注释、测试与文档中描述历史结构、历史行为或兼容处理。

## 事实源

- 范围、架构与验收以 `docs/plan/phase-<编号>-<slug>.md` 为准；存量计划以 `docs/plan/README.md` 登记的文件为准。
- 当前任务、执行空间、断点与恢复入口以 `docs/plan/progress/<同名计划>` 为准。
- Git 提交与验证结果只是完成证据，不能替代计划与账本。
- 账本只记录执行事实与证据，不复制计划；范围变化时修订计划，并在账本记录对当前执行的影响。

## 状态

未开始 / 进行中 / 阻塞 / 已完成。同一执行链同一时刻最多一个主任务处于“进行中”。

## 1. 制定计划

复制 `assets/plan-template.md`，至少写清：

- 头部：状态、关联 ADR、规格影响。
- 背景与目标、明确不做。
- 架构决策：只写当前方案，不保留旧方案的反向枚举。
- 数据流、涉及位置、任务边界与依赖。
- `## 规格与决策影响`：预期规格变更、需要新建或取代的 ADR、只在本期有效的局部决策。
- 每个任务有稳定唯一的 ID、实施内容、验证要求与依赖。
- 验收标准与风险/开放项。

计划不写执行过程、不写“进度以 Git 提交为准”，也不作为长期决策仓库。

## 2. 创建执行账本

- 路径：`docs/plan/progress/<计划文件名>`，不得直接放在 `docs/plan` 下。
- 复制 `assets/ledger-template.md`，记录计划路径、总体状态、worktree、分支、基线提交、当前 HEAD、工作区状态、当前任务与最近更新时间。
- 账本只由 mainAgent 维护；subagent 不得修改。
- 同一执行链同一时刻最多一个主任务处于“进行中”。

## 3. 执行与验收

- mainAgent：维护账本、准备任务简报、启动 subagent、接收报告、对照任务边界与验证要求验收、提交、决定下一步。mainAgent 不参与具体开发；需要代码审查时另起独立 subagent。收到报告后先同步账本状态、结果、验证证据与提交，再继续调度。
- subagent：完成分配任务的实现与自验证，返回实际变更、验证结果、规格影响（无 / 章节列表）、ADR 候选（有 / 无）、遗留问题与建议提交信息；不得修改账本、不得定稿 ADR/spec、不得执行仓库级 git 操作。
- 任务简报包含：目标、非目标、涉及文件、相关 spec 章节、约束、验证命令、输出格式。
- 验证命令：受影响包执行 `yarn workspace <pkg> test` 与 `yarn workspace <pkg> typecheck`；跨包逐个执行；需要全仓类型检查时执行 `yarn test:typecheck`。
- 需要下载第三方资源（docker image、CLI 等）时，提供命令由用户执行。
- 验收通过后立即提交，一个任务一个提交；账本随任务更新，不批量补提交。
- 任务开始、完成、阻塞、解除阻塞、执行空间变化、交接或准备中断时，立即更新账本。

## 4. 收口

- 全部任务完成后执行计划规定的总体验收；实现与验证都完成才可改为“已完成”。
- 把计划中的每个架构决策归类到 ADR、spec、TODO 或丢弃，并写入账本 `## 决策去向`；不得留空。
- 规格与代码、测试同一提交；更新 ADR 索引、`docs/plan/README.md`、`TODO.md` 与相关文档。
- 计划状态改为“已完成”或“已取消”并冻结；账本记录最终 HEAD、完整验证结果与遗留限制，永久保留。
- 合并到主分支时 squash 为单个提交。

## 5. 中断恢复

按顺序执行：

1. 读取原计划，确认范围、任务边界与验收标准。
2. 读取执行账本，定位当前任务、断点、阻塞与下一步。
3. 用 `git worktree list`、`git status --short`、`git rev-parse HEAD` 核对现场。
4. 现场与账本不一致时，先查明差异并更新账本，不得依据过期状态继续。
5. 一致后从账本记录的下一步恢复。

## 硬规则

- 不得写“实施进度以 Git 提交为准”。
- 不得让 subagent 修改执行账本或定稿 ADR/spec。
- 不得在计划完成后改写已冻结的计划；新方案另立计划。
- 不得在未获用户明确选择时处理兼容逻辑；选择不处理兼容后，不得以任何形式保留、识别或提及历史逻辑。
- 不得用对话上下文或 agent 内部计划替代计划与账本。

## 模板

- 计划：`assets/plan-template.md`
- 执行账本：`assets/ledger-template.md`
