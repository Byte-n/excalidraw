# 大场景性能优化计划

- 状态：待实施。
- 范围：Excalidraw 普通元素与 Mindmap 的视口筛选、指针命中和折叠可见性。
- 相关计划：[P10 移动端与大图性能](plan/10-mindmap-mobile-and-performance.md)。本计划使用其 500/2000 节点样例，并补充更大规模的混合场景；不改变 P10/P11 的完成状态。

## 目标与现状

目标是在场景元素很多、但视口内或折叠后实际可交互的元素较少时，减少平移、缩放和指针移动的主线程计算。完整场景数据仍用于保存、协作、历史、导出和整图编辑。

当前 [Renderer](../packages/excalidraw/scene/Renderer.ts) 先遍历全部非删除元素，排除折叠后代，再逐个判断是否进入视口；实际画布只绘制可见元素。[App.getElementsAtPosition](../packages/excalidraw/components/App.tsx) 在指针事件中遍历非删除元素，虽会在精确命中前跳过折叠后代，仍需逐个检查。Mindmap 布局已在折叠节点处停止向下遍历，无需重复改造。

[Scene.getMindmapHiddenElementIds](../packages/element/src/Scene.ts) 缓存隐藏 ID，但每次场景更新都会失效。[Scene.triggerUpdate](../packages/element/src/Scene.ts) 不提供变更元素明细，且有先批量原地修改、再统一通知的调用路径。这是增量索引必须先解决的正确性问题。

## 实施顺序

### 1. 建立性能基线

- 固定设备、浏览器版本、视口尺寸、设备像素比和缩放比例；记录样例生成方式与原始测量结果。
- 测试 500 可见节点、2000 总节点的既有样例，另建 10000 元素的分散场景、密集场景，以及大部分后代折叠的 Mindmap 场景。
- 对平移、缩放、连续悬停、拖动元素、折叠/展开和远端批量更新分别记录 p50/p95 帧耗时、长任务、内存，以及隐藏集合计算、候选筛选、精确命中、索引维护和静态绘制的耗时与候选数量。

### 2. 统一可见候选集

- 建立按场景版本缓存的可见元素集合，供 Renderer 和指针命中共同使用。折叠后代的节点、连线及绑定文字均从该集合排除；普通图形不受影响。
- 普通坐标或样式变化不应重算 Mindmap 的折叠关系。明确折叠状态、父子关系、图归属、增删及场景替换的失效规则；变更信息不足时执行完整重算。
- 先复用缓存列表消除每次指针事件的全场景隐藏 ID 检查，再测量这一阶段的收益，作为是否继续引入索引的对照。

### 3. 建立动态空间索引

- 在 `packages/excalidraw/scene` 中维护随 Scene 生命周期创建和销毁的索引服务，供 Renderer 与 App 共用。采用支持增删的 R 树实现；只索引当前可交互、可绘制的元素，并保留 `id -> 索引条目` 映射。
- 用场景坐标系的保守包围盒建立索引。视口变化只查询，不重建索引；指针查询使用包含现有命中容差的区域，结果继续经过原有精确命中、锁定、frame 裁剪和嵌入内容规则。
- 查询结果必须恢复场景层级顺序。渲染位置覆盖、新元素预览等临时视觉状态沿用现有专用路径，避免用文档坐标索引漏掉临时移动的元素。
- 折叠时批量移除隐藏分支，展开时按元素最新位置加入。折叠后代仍保留在 Scene 中，不把可见元素集合当成持久化数据。

### 4. 保证索引与场景同步

- 在单元素修改路径记录受影响 ID，并保存独立的旧包围盒条目；元素可能被原地修改，不能修改后才从元素对象读取旧坐标。
- 对批量替换、恢复、撤销/重做和协作更新比较旧新元素的 ID 与版本，只更新变化的条目。无法可靠识别变更的 `triggerUpdate()` 路径在查询前重建索引，并逐步补齐这些调用的变更记录。
- 将容器及绑定文字、Mindmap 节点及连线、frame 相关包围盒列为依赖更新；更改容器时同步更新受影响的候选条目。
- 用开发测试检查索引查询与现有全量扫描结果一致；索引失效时不得继续使用过期结果。

## 正确性回归

- 视口边界、旋转、自由绘制、绑定文字、图层顺序、锁定元素、frame 裁剪、嵌入内容和临时渲染位置覆盖。
- Mindmap 折叠/展开后绘图与命中立即更新；隐藏后代不能被直接命中，但选中或拖动根节点时仍随整图移动，框选整图仍扩展到隐藏后代。
- 创建、删除、原地拖动、批量布局、撤销/重做、保存恢复和双端协作更新后，索引与完整 Scene 保持一致。复用 [Mindmap 拖动测试](../packages/excalidraw/tests/mindmapDrag.test.tsx) 的既有语义。

## 验收与后续

- 对相同设备和样例给出优化前后 p50/p95、候选数量、索引维护耗时及内存对照。分散及大量折叠场景的平移/悬停 p95 以降低至少 30% 为初始目标；小场景与密集场景的 p95 回退不得超过 10%。基线显示瓶颈不在候选筛选时，应先重新定位瓶颈，不以索引接入本身视为性能验收通过。
- P10 的 500 可见节点拖动目标及 2000 总节点可用性目标继续单独验收；本计划不能用候选查询改善代替实际帧率和交互结果。
- 完成本期后重新分析静态画布绘制占比。若局部编辑仍因重绘大量可见元素而受限，再制定脏区域或图块缓存方案，并单独验证重叠、透明度、文字、阴影与 frame 裁剪。
