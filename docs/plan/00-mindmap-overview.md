## 已确定的交互规则

1. Mindmap 使用正式的 `mindmap-node`、`mindmap-edge` 类型及字段，不占用宿主 `customData`。
2. 普通节点只参与自动布局；拖动普通节点修改父子关系或同级顺序，不产生自由定位。
3. 拖动根节点执行整图平移，不改变树结构，也不能把根节点挂到其他节点下。
4. 混选普通图形和部分 Mindmap 节点时，选中集合自动扩展为整棵导图，选区覆盖整图当前可见范围；移动与拖动根节点一致。折叠后代虽然不参与普通框选，仍属于整图平移的数据范围。
5. 深层节点执行 `Shift+Tab` 时提升为父节点的同级；一级节点执行时连同子树拆成独立导图，使用新的 `graphId`，一次撤销可恢复。根节点不再提升。
6. 节点文字继续使用独立绑定文本；文字编辑及输入法组合期间保留文本编辑器的默认按键行为。
7. 一个用户操作及其自动布局只形成一次原子提交，布局不提供独立的手动命令入口。
8. 拖拽副本与目标连接预览、主题预览、导入预览和 AI 预览不提前写入正式场景、历史或协作数据。
9. 未适配的原生修改入口暂时禁用并提示，UI、键盘和命令入口保持一致，不能绕过 Mindmap 规则；普通图形的原有行为不受影响。
10. `Delete` 默认无弹窗删除节点及完整子树；`Shift+Delete` 删除节点并保留后代，仅多个直属子节点时弹窗。普通节点可选择将子节点依次放入原父节点下，或指定一个子节点接替原位置、接收其他子节点；接替操作仍在原图和原父节点下，不拆图。根节点的 Shift 删除则指定新根；零子节点直接删除，唯一子节点自动接替。

第 4、5 条为分期规划过程中用户明确确认的交互补充，实施时与原设计文档共同使用。

## 共用实现约束

### 统一命令与提交

- 统一链路：校验操作 → 计算结构 → 修复 edge → 计算布局 → 同步绑定文字 → 一次提交场景和历史。
- 键盘、控制点、上下文菜单、拖拽、大纲、导入、模板和 AI 复用相同命令，不各自维护一套结构逻辑。
- `parentId` 是关系来源，`order` 是同级逻辑顺序；不能用 edge、图层顺序或坐标倒推树结构。
- 结构、样式和布局变更只更新实际受影响的元素；恢复和修复保持确定性与幂等性。
- 可见布局结果合并回完整场景，不能用可见节点数组替换并丢失折叠后代。

### 代码组织与宿主边界

- 纯树算法、校验、布局继续放在元素层。
- 参照 [现有交互控制器拆分](../../packages/excalidraw/components/App.flowchart.ts)，拟新增独立的 `App.mindmap.ts`，避免将全部逻辑堆入 `App.tsx`。
- 通过现有 Action 提交机制接入历史；复用现有工具栏、菜单、文本编辑和侧栏机制。
- 新 DOM/browser API 使用 `app.ownerDocument`、`app.ownerWindow`；没有 `app` 时从挂载节点推导。
- 覆盖现有类型属性时优先使用 `Merge<Base, Overrides>`。
- P06 完成前，尚未适配的 Mindmap 协作修改入口需要保护，不能将普通元素的同步能力等同于结构协作已完成。

### 持久化与兼容

- 当期新增字段必须当期完成默认值、保存恢复、复制、换根和拆图兼容，不留到最后补。
- JSON 保存完整结构；PNG/SVG 默认只导出当前可见状态。
- 导航、选中、高亮和预览等本地状态不伪装成结构修改。
- 普通图形、普通 Arrow、宿主 `customData` 及既有文件行为保持不变。
- P06 之后新增的每种提交入口都要回归协作，不因协作期已结束而免除验证。

## 统一界面验收方式

每期交付以下内容，样例和预览在该期实施时提供，本次仅创建计划：

1. 可以打开的应用预览地址及明确的功能入口。
2. 可通过文件菜单加载的样例，包含普通图形、两张导图、多层分支及适用的折叠状态；P01 另需从空白画布开始验收。
3. 本期编号操作步骤、预期画面、取消行为和异常场景。
4. 单元测试、交互测试、浏览器实测结果及已知限制。
5. 对前期核心功能的回归结果。

基础人工样例统一使用“产品规划”根节点，下设“调研、方案、上线”；“调研”下设“用户访谈、竞品分析”，“方案”下设“原型设计”。需要破坏性测试时重新加载样例，避免用上一个用例的残余状态作为前提。

执行节奏固定为：实现一期 → 自测 → 用户界面审查 → 修正问题 → 用户确认 → 下一期。未通过审查的期次不能仅因后续代码已完成而标记完成。

## 共用完成门槛

- [ ] 本期所有交付功能均有 UI 或画布交互入口，关键命令不依赖控制台注入数据。
- [ ] 正常操作、取消、非法目标、边界状态均通过对应期的界面验收。
- [ ] 每个语义修改及其布局可一次撤销、一次重做；无变化和取消不新增历史。
- [ ] 保存重开保持完整结构；涉及复制和导出的期次通过相应往返测试。
- [ ] 所有结构操作保持单根、无环、无孤儿、确定顺序和正确文本/edge 关系。
- [ ] 折叠后代不会被普通框选命中，也不会因布局或保存意外丢失。
- [ ] 普通图形行为及前期功能无回归。
- [ ] P06 及之后通过双端协作回归；临时预览不会泄露到另一端。
- [ ] 新增逻辑有对应自动化测试，相关类型检查与格式检查通过；既有失败须单独记录。
- [ ] 用户通过界面审查确认本期完成。

结构不变量由自动化补足，不要求用户通过读代码或控制台完成验收。真实协作、真实 AI 和触屏手势不能仅凭 mock 测试宣布完成。
