## 用户可见目标

本期交付键盘操作、触屏命中区、单格无障碍代理及大表性能优化，保持现有整表覆盖的协作行为。下述更完整的并发、真实设备和辅助技术目标保留为后续设计，不计入本期完成范围。

## 实时协作与冲突：后续设计目标

本期产品决定保留 `TableDataV1` 文件格式和现有按表格元素版本覆盖的协作规则，不引入语义操作协议、房间级操作记录、删除墓碑或冲突副本；不要求旧客户端兼容。以下并发收敛与离线冲突条款保留为原设计目标，当前不实施，也不得作为已通过验收项。并发修改同一表格时，后续整表覆盖可能丢失另一端对不同行列的修改；删除与编辑、合并与结构变更也不具备下述逐目标冲突保证。

- 将插入、删除、排序、合并、拆分、尺寸调整、文字和样式编辑表示为有目标 ID 的语义操作；传输或重放前后验证行列/格引用、合并矩形与嵌套无环。单次用户操作在协作端作为一个原子结果可见。
- 两端在同一边界插入时，按稳定操作 ID 决定顺序，双方收敛；在不同行列编辑时保留双方修改。对同一行/列的并发尺寸或样式修改使用元素修订顺序决定最终值，并在界面反馈覆盖情况。
- 删除与修改同一目标并发时，删除优先；已删除目标的后续编辑不复活行、格或后代图形。用户能从本地撤销历史恢复自己的删除，但恢复需重新校验当前远端结构。
- 合并/拆分与行列结构变更并发时，按稳定 ID 重算目标区域；若目标已不存在或形成重叠合并，拒绝本次操作并提示重新选择，不能生成一张只在某一端有效的表。
- 拖动、缩放、插入线、选区、对齐线和远端光标只作为临时预览/在场状态，不进入持久化结构；释放时提交一次结果。撤销只撤销本用户操作，不覆盖其他用户后来完成的无关编辑。
- 离线编辑恢复后按语义操作重放和校验；无法自动合并时保留原数据与冲突副本，提供明确反馈，不能静默丢失子图形。

## 触屏与键盘：目标与交付边界

以下为完整交互目标。本期已交付及验证的部分见“实施与验收”；真实设备、屏幕阅读器和全部手势场景尚未验收。

- 手机和平板提供创建表格、选择格/行/列、拖入或添加图形、编辑背景文本、插入/删除、合并/拆分、调整尺寸、复制及撤销的可见入口。单元格范围选择沿用 [P02 的“单元格多选”开关及点击终点规则](phase-2.md#选择与命令)：模式内格内点击只选择单元格，表格外点击被阻止并提示；不支持在表格内拖动框选。模式外长按打开上下文命令，显式抓手移动行列；双指手势始终用于画布平移/缩放，避免误改表格。
- 触屏按钮和抓手的有效命中区至少 44 CSS px；缩放画布时命中区保持设备像素可用。手指遮挡插入线时，预览线和加号偏移到可见位置；拖放提交点与预览一致。
- 键盘可依次进入表格、可见单元格和子图形，方向键移动格焦点，Shift 扩展范围，Enter 编辑背景文本，Esc 逐级退出。结构命令有菜单入口，不依赖记忆快捷键；文字编辑及 IME 组合期不截获编辑器按键。
- 辅助技术读出表格尺寸、当前行列、合并跨度、单元格背景文本和子图形数量；合并格只进入一次焦点序列。虚拟焦点或可访问覆盖层按可见范围生成，避免为超大表创建数万个常驻 DOM 节点。

## 大表与深层嵌套：目标与交付边界

以下包含后续增量更新与真实移动设备目标。本期按表格数据对象缓存查询和绘制结果，并在 Chrome 桌面及触屏模拟环境完成固定场景基准。

- 建立以表格 ID、行列 ID、基础格 ID 为键的增量索引；命中与对齐只查询指针附近可见格。受影响子树增量更新渲染缓存，整体缩放预览可用临时矩阵，提交后统一写入规范几何。
- 可见窗口外的控制点、辅助线及辅助技术代理按需生成；普通子图形仍依画布可见范围裁剪。结构索引不改变内容绘制顺序、背景文本底层规则或溢出显示。
- 使用固定数据集验收：桌面 100×100 格、1000 个子图形、10 处合并和至少 3 层嵌套；移动端 30×30 格、200 个子图形。固定验收设备与浏览器版本，并报告创建、拖动、命中、缩放、保存及打开的 P95 耗时和峰值内存。
- 桌面连续拖动/缩放目标不低于 30 fps，普通格命中反馈 P95 不超过 50 ms；移动端主要操作不出现长时间无响应。若固定设备达不到目标，记录瓶颈并优化后再验收，不能仅凭小样本通过。

## 实施与验收

本期已实现内存表格查询索引、可见网格线段绘制、拖动子树的共享绑定集合、触屏 44 CSS px 结构命中区和按钮、选中格的 Enter/Esc/IME 键盘处理，以及单节点 ARIA 格代理。桌面和窄视口的固定规模浏览器基准由 `scripts/table-phase5-benchmark.cjs` 生成并验证，结果见下文。真实手机、平板及屏幕阅读器仍需人工验收，不计入本期完成结论。

固定环境：Apple M4、24 GB 内存、macOS 26.6.2、Chrome 154.0.8037.97（无头模式）。运行 `TABLE_BENCH_RUNS=10 node scripts/table-phase5-benchmark.cjs`，每种配置独立运行 10 次；下表耗时为跨运行 P95，帧间隔为每次操作的 P95 再取跨运行 P95，内存为采样点的最大 JS 堆使用量。移动端配置使用 390×844 Chrome 窄视口与触屏模拟，并非真实手机。

| 配置 | 创建 | 格命中 | 拖动/缩放帧间隔 | 保存 | 重开 | SVG 导出 | 采样堆峰值 |
| --- | --: | --: | --: | --: | --: | --: | --: |
| 桌面：100×100 格、1000 个图形、10 处合并、3 层嵌套 | 22.3 ms | 0.010 ms | 16.8/16.8 ms | 3.5 ms | 42.2 ms | 97.4 ms | 65.7 MiB |

拖动与缩放都验证了实际几何变化；按 P95 帧间隔换算约 59.5 fps。保存重开验证了元素数量、行列数和 10 处合并，SVG 导出验证了非空图形内容。触屏模拟验证了单格选择、44×44 CSS px 按钮、ARIA 行列数与单格代理，以及方向键和 Enter。堆内存只在命中前后与重开后采样，不代表浏览器进程的真实峰值。当前表格查询及绘制缓存按不可变 `TableDataV1` 对象重建，尚未提供按受影响子树增量更新或缩放临时矩阵；真实设备的手势冲突和辅助技术读出仍待验收。
