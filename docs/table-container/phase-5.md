# 第五期：协作、移动端与大表可用性

- 状态：设计方案，未实现。
- 前置：[P04 复制复用与原生格式](phase-4.md) 已通过所有结构命令和数据入口验收。
- 总体完成门槛：[全功能分期总览](00-overview.md)。

## 用户可见目标

多人同时编辑同一张表格时，结构、内容和样式最终一致；用户在手机、平板以及键盘/辅助技术环境中能完成核心工作；大表格和深层嵌套仍能流畅选择、拖入、缩放和保存。

## 实时协作与冲突

- 将插入、删除、排序、合并、拆分、尺寸调整、文字和样式编辑表示为有目标 ID 的语义操作；传输或重放前后验证行列/格引用、合并矩形与嵌套无环。单次用户操作在协作端作为一个原子结果可见。
- 两端在同一边界插入时，按稳定操作 ID 决定顺序，双方收敛；在不同行列编辑时保留双方修改。对同一行/列的并发尺寸或样式修改使用元素修订顺序决定最终值，并在界面反馈覆盖情况。
- 删除与修改同一目标并发时，删除优先；已删除目标的后续编辑不复活行、格或后代图形。用户能从本地撤销历史恢复自己的删除，但恢复需重新校验当前远端结构。
- 合并/拆分与行列结构变更并发时，按稳定 ID 重算目标区域；若目标已不存在或形成重叠合并，拒绝本次操作并提示重新选择，不能生成一张只在某一端有效的表。
- 拖动、缩放、插入线、选区、对齐线和远端光标只作为临时预览/在场状态，不进入持久化结构；释放时提交一次结果。撤销只撤销本用户操作，不覆盖其他用户后来完成的无关编辑。
- 离线编辑恢复后按语义操作重放和校验；无法自动合并时保留原数据与冲突副本，提供明确反馈，不能静默丢失子图形。

## 触屏与键盘

- 手机和平板提供创建表格、选择格/行/列、拖入或添加图形、编辑背景文本、插入/删除、合并/拆分、调整尺寸、复制及撤销的可见入口。长按打开上下文命令，显式抓手移动行列；双指手势始终用于画布平移/缩放，避免误改表格。
- 触屏按钮和抓手的有效命中区至少 44 CSS px；缩放画布时命中区保持设备像素可用。手指遮挡插入线时，预览线和加号偏移到可见位置；拖放提交点与预览一致。
- 键盘可依次进入表格、可见单元格和子图形，方向键移动格焦点，Shift 扩展范围，Enter 编辑背景文本，Esc 逐级退出。结构命令有菜单入口，不依赖记忆快捷键；文字编辑及 IME 组合期不截获编辑器按键。
- 辅助技术读出表格尺寸、当前行列、合并跨度、单元格背景文本和子图形数量；合并格只进入一次焦点序列。虚拟焦点或可访问覆盖层按可见范围生成，避免为超大表创建数万个常驻 DOM 节点。

## 大表与深层嵌套

- 建立以表格 ID、行列 ID、基础格 ID 为键的增量索引；命中与对齐只查询指针附近可见格。受影响子树增量更新渲染缓存，整体缩放预览可用临时矩阵，提交后统一写入规范几何。
- 可见窗口外的控制点、辅助线及辅助技术代理按需生成；普通子图形仍依画布可见范围裁剪。结构索引不改变内容绘制顺序、背景文本底层规则或溢出显示。
- 使用固定数据集验收：桌面 100×100 格、1000 个子图形、10 处合并和至少 3 层嵌套；移动端 30×30 格、200 个子图形。固定验收设备与浏览器版本，并报告创建、拖动、命中、缩放、保存及打开的 P95 耗时和峰值内存。
- 桌面连续拖动/缩放目标不低于 30 fps，普通格命中反馈 P95 不超过 50 ms；移动端主要操作不出现长时间无响应。若固定设备达不到目标，记录瓶颈并优化后再验收，不能仅凭小样本通过。

## 实施与验收

1. 抽出全部结构命令的目标 ID、前置条件和确定性冲突处理；用两个独立浏览器会话覆盖并发与离线恢复。
2. 完成手机、平板及键盘/屏幕阅读器的真实交互，检查文本输入、触屏抓手与画布手势冲突。
3. 建立固定规模场景、性能采集和回归门槛，优化命中、渲染、预览与保存链路。

- [ ] 两端并发插入、删除、移动、合并、修改背景文本和缩放后结构一致，无重复行列、重叠合并、孤儿图形或失效绑定。
- [ ] 离线重连、撤销重做、冲突拒绝和远端光标不改变不变量；临时预览不进入文件。
- [ ] 手机和平板可完成创建、拖入、背景文本编辑、行列结构与合并操作；抓手、插入线和菜单可命中且不误触画布双指手势。
- [ ] 键盘和辅助技术可遍历可见格、识别合并跨度、进入背景文本与内部图形，IME 不被结构命令干扰。
- [ ] 固定大表场景达到记录的帧率与命中目标；保存重开和导出仍保持完整结构与画面。
