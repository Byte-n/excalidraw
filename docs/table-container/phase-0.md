# P00：统一画框类容器的直接父关系

- 状态：设计方案，未实现。
- 定位：为表格等后续容器建立统一的直接父引用。
- 后续：[P01 表格核心容器](phase-1.md) 在本期的统一父引用上增加单元格分支。
- 总体完成门槛：[全功能分期总览](00-overview.md)。

## 目标与范围

普通画框 `type: "frame"` 和 Magic Frame `type: "magicframe"` 使用同一种直接父关系。图形只记录直接所属的画框类容器；容器按直接成员递归处理后代。本期完成两种画框的创建、包裹、移动、选择、裁切、复制、删除、保存与导出，不创建表格。

每个画布元素至多有一个直接空间父容器，`containerRef` 是唯一持久化的空间父字段。`groupIds` 表示分组选择，绑定文本的 `containerId` 表示文本宿主，两者不替代空间父关系。后续容器类型通过扩展父引用的判别联合接入。

## 数据契约

```ts
type FrameLikeContainerRef = Readonly<{
  kind: "frameLike";
  elementId: string;
}>;

type DirectContainerFields = Readonly<{
  containerRef?: FrameLikeContainerRef;
}>;
```

- `elementId` 必须指向未删除的 `frame` 或 `magicframe` 元素。画框类元素在本期位于画布顶层，不互相嵌套；没有直接父容器的元素省略 `containerRef`。
- 画框不持久化成员 ID 列表。直接成员以自身的 `containerRef` 为唯一归属来源；运行时建立 `elementId -> 直接成员 ID` 反向索引。矩形相交只参与加入画框的交互判定，加载时不根据几何重新推断归属。
- `x`、`y` 是场景坐标。移动画框更新画框与全部成员的几何，每个元素只变换一次；引用不保存局部坐标或额外位移。排序、裁切、复制、删除和导出均使用同一父关系。
- 绑定文字通过 `containerId` 关联宿主并继承宿主的空间归属；分组的直接成员分别记录父引用。绑定、分组及空间父链各有独立职责，不重复保存同一归属。
- 场景输入校验引用目标类型、缺失目标、自引用和父链环；不合法数据明确报错，不生成悬空成员。

## 实现范围

1. 在元素公共类型、创建命令、场景更新和公开元素数组中定义规范的 `containerRef`；画框成员查询、加入/移出、拖动、选中、裁切及图层顺序共同使用直接父解析。
2. 复制时重映射画框与成员 ID；删除、撤销重做、文件、库、剪贴板和 PNG/SVG 导出按父链处理完整子树。Magic Frame 的包裹与生成入口使用同一成员关系。
3. 从提交后的场景构建或增量维护反向索引；预览状态不写入持久化关系。每次结构提交及协作更新后校验引用与无环约束。

## 验收

- [ ] 从空白画布创建普通画框和 Magic Frame，分别包裹多个图形；成员独立编辑，移动画框时成员同步移动且不重复变换。
- [ ] 两种画框的选择、命中、裁切、图层顺序、复制、删除、撤销重做、保存重开和 PNG/SVG 导出使用同一直接父关系。
- [ ] Magic Frame 的内容包裹与生成使用准确的成员集合；绑定文字和分组成员的归属可解析，不产生重复成员。
- [ ] 场景、库、剪贴板及公开 API 的元素数据只有规范的父引用；无效目标与父链环有确定处理结果。
- [ ] 两个独立会话更新不同画框成员后引用一致；相同成员的并发归属更新按元素修订顺序协调，无孤儿或环。
