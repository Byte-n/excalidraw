# 表格容器图形：全功能分期总览

## 定位与完成标准

表格是白板上的网格容器，不是电子表格。单元格能容纳画板支持的任意图形，包括另一个表格；双击单元格编辑其背景文本，背景文本始终位于格内普通图形之下。拖入图形的提示属于图形本身，单元格内虚线是对齐辅助线。

本计划覆盖表格从创建到复杂结构编辑、样式、复用、互通、协作及移动端的完整白板工作流。所谓“完整”以本页能力矩阵和各期验收为准；公式、数据排序筛选、数据库字段约束等电子表格功能不属于此图形。所有期次目前都是**设计方案，未实现**；文档中的目标不代表仓库已有对应能力。

实施依据：[复合图形数据结构总纲](../composite-shape/design.md) 与已提供的 Lark 白板表格五种界面状态。样本文件 [lark-examples-data.json](../composite-shape/lark-examples-data.json) 中有 3 个 `table`、4 个 `table_er`、2 个 `table_uml`、2 个 `combined_fragment`，覆盖普通格、跨行/跨列合并、单元格文字/填色和表格边框。样本不是原平台全部交互规格；无法从样本验证的行为以本方案明确规定，并在界面验收中核对。

## 跨期不变量

1. `type: "table"` 表示语义容器；行、列、单元格使用正式结构字段与稳定 ID，不藏在 `customData`、`groupIds` 或 `frameId` 中。普通图形的直接归属、绑定文字的继承归属及嵌套表格的直接父关系必须可校验且无环。
2. 单元格背景文本与普通文本图形分开；前者在所在格内容的最低层，非编辑态不抢占拖入和图形选择。合并格也不得丢失任何原背景文本。
3. 拖放预览与提交使用同一目标格判定。结构修改、子树几何、文字模式和绑定更新组成一次用户操作、一次历史记录；取消不改场景。
4. 整体缩放时，支持文字的图形转入固定模式。P01 等比，P03 才开放不等比；行高/列宽的局部调整属于另一种操作，不改变普通图形的字号或模式。
5. 行列尺寸和表格外框始终一致；合并区域不重叠，成员格可追溯；删除、复制、恢复、并发重放后无悬空归属。
6. 普通图形、画框、分组、箭头绑定及现有文件行为不因表格而失效。表格的视觉溢出不等于自动改写归属。
7. 画布渲染、命中、导出和缩略图共用规范几何及层级；明暗主题下可辨识。虚线表示图形对齐，不表示单元格分割。
8. 不支持的外部字段、版本或格式须明确反馈，不能静默丢弃内容或把其他语义元素伪装成普通表格。

## 统一实现与验收门槛

- 元素层提供纯结构命令和校验：创建、插入、删除、排序、尺寸调整、合并、拆分、区域变换和归属解析。画布控制器负责命中、预览和提交；各入口复用同一命令，不在菜单、手势和导入中分别实现规则。
- 每期交付可打开的应用预览、从空白画布开始的操作步骤、包含普通图形和嵌套表格的样例、自动化与人工验收结果。无 UI 入口的底层数据能力不算完成。
- 每个语义操作一次撤销、一次重做；保存重开和重复恢复稳定；复制后 ID 与引用正确；取消和无变化不增加历史。
- 文件、库、剪贴板、公开 API、PNG/SVG 等入口均验证相同不变量；新增持久化字段当期完成版本与恢复策略。后续期次变更结构时负责旧版表格数据迁移。
- 交互至少在明暗主题、缩放画布、旋转表格、中文输入、长文本、复杂子图形及嵌套场景中检查。P05 增加真实双端协作、触屏设备和固定数据集性能采集。
- 对性能和协作有风险的操作，先在临时预览中计算，再原子提交；绝不把拖动中间帧、选区或悬停写入场景与协作数据。

## 最终验收场景

1. 创建普通 3×3 表格，双击不同单元格写背景文本，拖入文本、图形、图片、箭头及嵌套表格；对齐线、选择层级和越格显示正确。
2. 增删、排序、调整行列，合并跨行跨列区域并拆分；任何原内容、绑定与背景文本都可恢复。复制表格与区域后可独立编辑。
3. 等比和不等比缩放含长文本与多层嵌套的表格；模式、字号、几何、最小尺寸和撤销正确，文本不撑大单元格。
4. 分别设置表格、行列、格的底色、边框、文字样式、对齐和标题；明暗主题、画布、PNG/SVG 与重新打开的结果一致。
5. 导入现有 11 个 Lark 表格类样本，检查合并、尺寸、文字、主题色及变体语义；对不能表达的字段得到明确报告。原生文件和库往返无丢失。
6. 两端同时编辑行列、合并与内容，并在手机和平板上完成主要操作；最终结构一致，无孤儿和环，大表仍能流畅定位与编辑。
